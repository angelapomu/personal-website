# 项目详情页 Layout UI 规范

版本：2026-11-21 · V3

本文只规定页面结构、组件用途、尺寸、间距和响应式行为。它是后续详情页排版的统一依据，替代本文件旧版的多色卡片、自由列宽与不统一的标题位置规则；不代表现有页面已经全部符合。

## 1. 排版的基本逻辑

页面只有三种组织方式：

1. **章节与 sub-section 组织内容层级。** 它们决定内容属于哪里。
2. **段落、列表、卡片和表格组织阅读方式。** 它们决定同一层级里的内容如何呈现。
3. **diagram、screenshot、数据条是证据或媒体模块。** 它们归属某个章节或 sub-section，不另造内容层级。

卡片是容器，不是新的分类或标题级别。不能因为一段内容想加边框，就改变它在原文中的层级。也不能把每一个 bullet 自动转换为一张卡片。

所有文案、大小写、标点及 Markdown 标题层级沿用用户原稿。排版不能新增解释、结论、小标题、标签或数字；已有明确批注允许拆标题的地方按批注执行。

## 2. 页面骨架与宽度

```text
吸顶导航（64px）
项目首屏（四个详情页统一）：项目图标在左，项目名 / subtitle 在右
                  分隔线
                  元信息横排（label 与 value 相邻）
试用链接（如有，紧接项目首屏下方）
概览卡片组（如有）
产品截图组（如有）

侧边目录       正文
              章节标题
              ├─ 原有段落
              ├─ sub-section 标题
              │  ├─ 段落 / 列表 / 卡片组
              │  └─ 图 / 表 / 数据
              └─ 下一 sub-section
```

- 页面外框最大宽 1200px，左右居中；宽屏左右安全边距 48px，小屏 24px，400px 以下 20px。
- 正文区最大宽 800px，最小宽 0，内容不超出正文边界。
- 目录宽 160px，目录与正文间距 48px。视口小于 1100px 时隐藏侧栏，使用导航下方的章节标签；优先保证正文宽度。
- 正文左边界贯穿章节标题、段落、列表、表格及图片；卡片组外边界也与正文对齐。
- 阅读顺序始终为从上至下、从左至右。小屏改为单列时保持 DOM 顺序。
- 页面首屏、概览与正文之间间距 64px；手机 40px。
- 四个详情页使用相同的首屏结构与图标位置；首屏内容最大宽 1104px，标题行、元信息与下方内容按同一左边界对齐。
- 项目试用链接（如有）放在首屏 Hero 外部紧接其下方、概览卡片组之前；不在正文结论中重复。

## 3. Title、subtitle 与原稿层级

项目名只在首屏使用一个 H1。正文里的原稿 `#`、`##`、`###` 分别映射为 H2、H3、H4，不新增或跳级。

| 角色 | 使用位置 | 桌面字号 / 行高 / 字重 | 手机字号 |
| --- | --- | --- | --- |
| 项目图标 | 首屏标题行左侧 | 92×92px | 72×72px |
| 项目 title / H1 | 首屏项目名 | 64px / 1.15 / 800 | 38px |
| 项目 subtitle | 原稿已有的项目简介或副名 | 20px / 1.6 / 400 | 18px |
| 章节 title / H2 | 原稿 `#`，也是目录项 | 34px / 1.3 / 700 | 28px |
| sub-section title / H3 | 原稿 `##` | 24px / 1.4 / 700 | 22px |
| 次级 sub-section title / H4 | 原稿 `###` | 20px / 1.5 / 600 | 20px |
| card title | 卡片中已有的标题 | 20px / 1.5 / 600 | 20px |
| 正文与 bullet | 原文段落、列表、卡片内容 | 17px / 1.85 / 400 | 17px |
| 元信息与图注 | label、caption | 14px / 1.6 / 400 | 14px |

- 全页中文使用同一字体族；字号和间距承担层级，不用多种字色或混合字重制造额外层级。
- 首屏标题行固定为“项目图标 → 项目名 / subtitle”，图标与标题垂直居中；四个详情页保持一致，不把图标移到标题右侧。
- 元信息位于标题行下方，顶部使用 1px 浅色分隔线，间距 24px；label 与 value 并排，多个字段按横向顺序排列。窄屏允许字段组自然换行，label 与对应 value 保持相邻。
- 首屏 Hero 使用统一浅粉底色；桌面上下内边距为 64px / 40px，手机为 40px / 32px。
- 试用链接（如有）使用 16px / 1.6 的文字链接，放在 Hero 下方、概览卡片之前；沿用原有链接文案，只出现一次。
- 相邻标题与其内容保持同一左边界。
- 英文允许自然换行，不把已有单词逐字拆开；标题不能与其第一段分离到不同模块。
- 一段话中的个别数字不单独放大或着色；需要数据展示时使用第 9 节的数据模块。

## 4. Sub-section 的统一形态

一个 sub-section 固定为：**标题 → 内容模块 → 下一 sub-section**。

- 标题在模块之外，适用于它统领多段内容、列表、表格或图片的情况。
- 如果原有标题及其内容一起被放入一张卡片，标题就放在卡片内部；外面不再重复一个标题。
- sub-section 之间留白 40px；手机 32px。标题与首个内容模块之间 16px。
- 同一 sub-section 内的段落间距 16px，模块间距 24px。
- 章节之间留白 64px，并使用一条浅色分隔线；sub-section 之间不默认添加分隔线。
- 同层级内容必须使用同一标题字号、间距与对齐方式。正文、卡片标题都不能模拟成另一层级的大标题。

## 5. 单一 Card 组件

**正文内容卡片只使用一种外观。** 包括研究卡、用户卡及产品设计卡。唯一例外是首屏之后的四张概览卡：按阅读顺序，第 1 张浅粉色 `#FBDDE8`、第 2 张玫粉色 `#F29BBF`、第 3 张浅米色 `#EBE3DB`、第 4 张白色 `#FFFFFF`。颜色绑定卡片位置，不绑定 role、痛点、方案或成果等内容名称；桌面按从左到右、从上到下，手机按从上到下，内容顺序保持原样。其余布局规则一致。正文卡片不得沿用这个颜色例外。

| 属性 | 统一规则 |
| --- | --- |
| 卡片底色 | 白色 `#FFFFFF` |
| 边框 | 1px 浅灰 `#DDD6CF` |
| 圆角 | 8px |
| 阴影 | 无 |
| 内边距 | 24px，手机 20px |
| 标题位置 | 卡片内部顶部，左对齐 |
| 标题到内容 | 16px |
| 正文 | 使用正文统一样式，禁止单卡放大、变色 |
| 卡片之间 | 20px，手机 16px |
| 高度 | 自适应内容，不指定高度、不裁切、不折叠正文 |

```text
┌──────────────────────────────┐
│ 24px                         │
│ 原有标题                     │
│                              │
│ 原有段落或 bullet list       │
│                         24px │
└──────────────────────────────┘
```

- 不为卡片增加序号、角标、emoji、装饰性图标或不同强调色。
- 卡片标题跟随原稿语义：已有标题继续使用其原有 H 级别；仅作为条目标签的标题不强行提升为章节。
- 一张卡片只包裹一个独立主题。没有独立标题的多个同类 bullet，应首先保持为列表。
- 静态信息卡不使用手形光标、悬浮升起或可点击外观；确有交互时才增加对应控件与焦点状态。

## 6. Card group 与列数

卡片组只有**等宽双列**和**顺序单列**两种布局。禁止 1.3:1 的临时比例、三张卡片出现“上二下一”或仅把最后一张拉满。

- 依据卡片组实际可用宽度决定列数，不只看整个浏览器宽度。
- 容器宽度达到 720px，且每张卡片内容适合在至少 350px 内阅读，才能使用双列。
- 容器宽度小于 720px，或两侧内容量明显不适合并排时，整组单列。
- 两张卡并排：等宽、标题顶端对齐、卡片外框同一基线；不为了填满空间拉大字距或行距。
- 三个没有独立标题的同类要点：使用一个连续列表，不使用三张独立卡片。
- 四张概览卡：宽度足够时为 2×2，不足时顺序单列。
- 一个组内不能混用标题在框内、标题在框外两种形式。

## 7. Bullet 与段落

列表呈现**并列要点**，卡片呈现**独立主题**，两者不互相替代。

- 默认 bullet 保留列表标记，列表整体左对齐，悬挂缩进约 1.2em，条目间距 12px。
- 同一连续列表中的条目不各加边框，不对长条目单独扩大宽度。
- 带有原有“名称：说明”的条目，经用户明确允许后，名称可作小标题，说明作段落；各条保持同样的标题样式和模块间距。
- 嵌套列表保留原层级，内层缩进 1.2em，不能因为放进卡片而压成一行。
- 不为统一排版拆改原句、增加连接词或删除标点。

## 8. Table

表格只用于**相同字段下比较多项内容**，不是普通段落的收纳框。

- 使用完整的横竖细边框、左对齐表头、顶端对齐的单元格；正文 16px / 1.8，表头 16px / 1.6 / 600。
- 单元格内边距 16px，表头使用白色或统一中性浅灰；不为每列、每行指定不同主题色。
- 表格外边界与正文一致，不出现顶部粗黑线。
- 容器不足以清晰显示列内容时，整张表改为逐行条目：第一列作条目标题，其余字段以“字段名 + 内容”纵向排列。
- 手机不采用横向拖动才能读完整一行的表格。转换后保留表头语义和字段关联，字段名不能丢失。

## 9. Data / 指标条

- 原稿明确需要独立展示的数据，使用数字在上、标签在下的指标条；不自动从原文复制数据制造第二套摘要。
- 数字 40px / 1.2 / 700，标签 14px / 1.6 / 400；手机数字 32px。
- 数字与标签间距 8px，指标间距 24px；每项最小宽 140px，按内容宽度自然降为两列或单列。
- 使用统一文字颜色，无顶部黑线、无彩色底块、无每项独立卡片边框。
- 指标说明和限定条件使用原有正文；排版不改变数值、单位或口径。

## 10. Diagram / 架构图与流程图

```text
原稿已有的标题
16px
┌──────────────────────────────┐
│ 流程图 / 架构图（完整比例）    │
└──────────────────────────────┘
12px
原有图注（如有）
```

- 每张图为独立 figure，默认占正文全宽，contain 展示，禁止裁剪、拉伸、叠加装饰性卡片。
- 标题在图片外部上方，图片本身不再重复加一套标题栏；图注在下方左对齐。
- 图周围使用统一 1px 浅边框；不加彩色背景或大面积阴影。
- 未提供原图时使用统一 16:9 中性占位框；标识一次图名即可，不写入自行推演的节点。
- 正式图按原始比例显示，不继续强制 16:9。
- 支持点击放大、键盘打开、关闭及焦点返回；小屏不把多张图并排挤小。

## 11. Screenshot / 截图

- 截图作为产品证据单独成组，不能和文本卡片混在同一个 grid 中。
- 一个截图：单图展示；多个截图：依据每张至少 180px 的宽度排列，最多四列，小屏一列或两列。
- 保留原图比例、文字与完整界面；使用 contain，不把手机截图强行裁成方形。
- 图注紧跟图片下方，14px，间距 12px；只使用原有标题和图注。
- 同组截图的外框、间距、图注位置统一。实际截图内部的颜色不属于卡片底色规则。
- 只有项目图标时在首屏使用，不在正文重复放大为截图展区。

## 12. 针对当前三处批注的应用

| 当前位置 | 统一后的组件 | 布局处理 |
| --- | --- | --- |
| 竞品分析中的三个未满足痛点 | 连续 bullet list | 三条顺序排列，取消独立边框与最后一项跨列 |
| 情感需求洞察 / 目标用户 | 同一种 Card 的一组实例 | 都用白底、相同边框、内部标题和正常正文；内容宽度不足 720px 时整组单列 |
| 搭子性格设计 / MVP功能设计 | 同一种 Card 的一组实例 | 与上一组完全相同；段落和嵌套 bullet 可不同，外框、标题位置和字体规则相同 |
| 关键决策中的已拆标题条目 | Sub-section | 保留已获准的小标题与正文形式，使用统一模块间距 |
| 流程图 / Agent架构图 | Diagram placeholder | 全宽、中性占位、标题只出现一次，等待原图替换 |

**同一信息不叠加多种外观。** 一组内容只能选择列表、卡片组或表格中的一种；不同时增加彩色底、单词放大、子卡片和额外分隔线。

## 13. 布局验收

- 原稿的文字和 `# / ## / ###` 关系可以逐项对应。
- 所有正文卡片底色、边框、圆角、标题位置、内边距一致；只有开头四张概览卡允许使用规定的原始配色。
- 正文中没有无理由的“上二下一”、不等宽卡片或只给个别数据加色放大。
- 938px 视口隐藏侧栏，给正文留足宽度；卡片列数继续按正文容器宽度判断。
- 1440px、938px、768px、390px 下均无整页横向滚动、重叠或文字裁切。
- 标题、正文、卡片、图片之间只使用本规范的间距，不逐块临时手调。
- 目录选中态只指向一个当前章节；吸顶导航不盖住跳转目标。
- 桌面、手机和独立导出的 HTML 使用同一套组件规则。
